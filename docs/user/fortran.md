# Coupling an existing Fortran code

FUSE's participant ABI (see [](c-abi.md) for the C side and [](../dev/abi-design.md) for why it is
shaped the way it is) gives Fortran a module, `ffuse`, generated by `tools/gen-abi.py` from the same
entry list the C header is generated from — the module and the header cannot disagree, because
nothing hand-written stands between either of them and `include/fuse/abi/entries.def`.

Fortran does not get the C side's one-exported-symbol table: dereferencing a struct of function
pointers from Fortran is unpleasant enough that `ffuse` is a deliberate second ABI instead, a small
family of flat `bind(C)` symbols, `ffuse_<entry>`, exported from a separate library,
`libfuse-abi-fortran` — so `libfuse-abi` (the C side) still exports exactly the one symbol
`fuse_coupler_abi`. Every `ffuse_<entry>` just forwards to that table at first use.

## A complete minimal program

```fortran
program couple
  use, intrinsic :: iso_c_binding
  use ffuse
  implicit none

  type(fuse_ctx) :: ctx
  type(fuse_null) :: nothing
  type(fuse_context_out) :: made
  type(fuse_field_ref) :: heat_flux
  type(fuse_field_view) :: view
  type(fuse_ongoing) :: ongoing
  type(fuse_step_report) :: report
  real(c_double), target :: q(100)
  integer(c_int32_t) :: status

  status = fuse_create(ctx, nothing, made)      ! ctx must be NULL on entry
  ctx%ptr = made%ctx                            ! ... and holds the new context after

  status = fuse_load_graph(ctx, "coupling.yaml", nothing)   ! string convenience overload

  status = fuse_field_handle(ctx, "fluid", "heat_flux", heat_flux)

  view%handle       = heat_flux%handle
  view%element_type = FUSE_ELEMENT_F64
  view%memspace     = FUSE_MEMSPACE_HOST
  view%components   = heat_flux%components
  view%count        = size(q, kind=c_int64_t)
  view%owned_count  = size(q, kind=c_int64_t)
  view%stride       = 1_c_int64_t
  view%data         = c_loc(q)                  ! q must stay valid until destroy()
  status = fuse_register_field(ctx, view, nothing)

  status = fuse_initialize(ctx, nothing, nothing)

  status = fuse_is_coupling_ongoing(ctx, nothing, ongoing)
  do while (ongoing%ongoing /= 0)
    status = fuse_begin_step(ctx, "fluid", report)   ! q is current on return
    call advance_my_solver()
    status = fuse_end_step(ctx, "fluid", report)      ! q is read here
    status = fuse_is_coupling_ongoing(ctx, nothing, ongoing)
  end do

  status = fuse_destroy(ctx, nothing, nothing)
end program couple
```

Every member has the shape `fuse_<entry>(ctx, in, out)`, matching the C side's
`fuse_status name(fuse_ctx* ctx, const IN* in, OUT* out)` member-for-member — `in`/`out` are
`fuse_null` where C passes `NULL`. `status` is the function result, compared against the
`FUSE_OK` / `FUSE_ERR_*` parameters `ffuse` also exports.

## Type mapping

| In `entries.def` | In Fortran | Note |
|---|---|---|
| argument struct `fuse_x` | `type, bind(C) :: fuse_x`, members in the same order | `C_SIZEOF` of the Fortran type equals the C `sizeof`; pinned for every struct by `test/abi/struct_sizes.golden` (ctest `abi.fortran_sizes`) |
| `uint32_t`, `int32_t` | `integer(c_int32_t)` | unsigned fields hold values below 2³¹ by construction (`FUSE_ABI_MAX_STRUCT_SIZE`) |
| `int64_t`, `uint64_t` | `integer(c_int64_t)` | |
| any pointer | `type(c_ptr)` | `c_loc()` of a `target` array; the caller keeps it alive the same way the C rule requires |
| `fuse_exact_time`, `fuse_semantic_version` | `type, bind(C)` of the same name | closed value types, no `struct_size`, never grow |
| `fuse_ctx*` (the leading argument of every entry) | `type(fuse_ctx)` wrapping one `type(c_ptr)` | opaque; `create()` fills `%ptr`, `destroy()` ends it |
| entry `name` | `fuse_name(ctx, in, out)`; link symbol `ffuse_name` | every entry, without exception: no type shares an entry's name |
| `FUSE_OK`, `FUSE_ERR_*`, `FUSE_ELEMENT_*`, ... | `integer(c_int32_t), parameter` of the same name | |

**`struct_size` is set by the module, not by you.** Every generated `fuse_name` sets
`in%struct_size`/`out%struct_size` from `C_SIZEOF` before making the call; you never read or write
those members yourself. A program compiled against an older `ffuse` keeps running against a newer
`libfuse-abi` for the same reason a C caller does — the oldest struct_size it sends is always
faithful to what it was actually compiled against.

**Defaults are default initialisation.** Every argument type initialises each member to its
documented default (`0`, `c_null_ptr`, `fuse_exact_time(0, 1)`), so declaring one and setting only
the members you need passes exactly what a C caller passing a zeroed struct would.

**Strings** are ordinary `character(len=*)` at four call sites — `load_graph`'s YAML path,
`field_handle`'s component and field names, and `begin_step`/`end_step`'s component name — generated
as an overload of the same `fuse_<entry>` name alongside the struct-taking form; pass either one.
`fuse_last_error(ctx, message, truncated)` is the same idea on the way out: it fills a
`character(len=*)` for you and reports truncation through an optional `logical`, rather than making
you manage the `fuse_error` struct's `buffer`/`capacity`/`length` members directly (though that raw
form is still there if you want it).

**Communicators** are the Fortran MPI handle — `fuse_setup_options%communicator`, `integer(c_int64_t)`,
built from `MPI_Comm_c2f` on your side; FUSE recovers it with `MPI_Comm_f2c`, the same convention
`MoabMeshBackend::set_communicator` uses everywhere else in this library. Leave it `0` (the default)
to run with no communicator at all.

## Building

```
cmake -S . -B build -DFUSE_ENABLE_FORTRAN=ON   # ON is the default when a Fortran compiler is found
cmake --build build --target fuse-abi-fortran
```

`FUSE_ENABLE_FORTRAN` is ON by default; it turns itself back off, with a message rather than a
configure error, on a machine with no Fortran compiler. Link `fuse::abi-fortran` (the installed name
is the same, via `find_package(fuse-coupler)`):

```cmake
find_package(fuse-coupler CONFIG REQUIRED)
target_link_libraries(my_participant PRIVATE fuse::abi-fortran)
```
