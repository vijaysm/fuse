## 4. Overall build/CI health assessment

The **build system itself is unusually strong**: the dependency-resolution layer encodes dozens of
measured, real defects (stale MOAB configs, alias-target properties, fetch-path scoping, ArborX's leaked
`ARBORX_ENABLE_MPI`, nvcc arch gaps) with correct fixes, install/export is complete and consumer-tested in
three places, and the gate scripts embody a rare "accumulate-and-report, never-false-green" discipline.

The **weak plane is the enforcement perimeter around CI**, in three layers: (1) the workflow has a leg
that is now guaranteed-red (`builtin`, BC-1) because D26 landed after the matrix was authored — masked in
practice only because CI has run once, ever, with unrecorded results; (2) the mutation-evidence invariant
(I9) claims a CI gate that does not exist, and its anchors have already rotted in exactly the way that
absence permits (BC-2/BC-3) — the single most actionable finding, since `--check-anchors` is static,
sub-second, and ready to add to the `gates` job today; (3) several "Enforced by X" claims in
invariants.md/conventions.md name mechanisms (sanitizer leg, clang-tidy, fmtlog logger) that are absent
from both the workflow and the tree — the docs' honesty elsewhere makes these stale enforcement claims
stand out.

Priority order within this report: fix the two red gates (re-anchor 3 mutations; resolve or drop the CI
`builtin` leg), add `--check-anchors` to the `gates` job, then sweep the fmtlog dead code and the stale
"Enforced by" claims.
