## 2. Checked and found clean

- **One symbol per ABI.** `fuse_coupler_abi` is the sole ELF export (`exported_symbols.map`, `.sym`, `-fvisibility=hidden`), asserted by `abi.exported_symbols` (nm "defined text" only, both ELF and Mach-O). Shim exports only `ffuse_*`, enforced by `abi.fortran_exports` including the "no `fuse_*` at all" rule.
- **No macros in public headers.** `types.h`/`participant.h`/`provider.h` contain only include guards and `extern "C"`; `entries.def` is the documented internal X-macro list and is *not installed*. `.clang-tidy` opt-out present, matching conventions.md.
- **I1 exact time.** No floating-point time anywhere in the ABI: all time-carrying members are `fuse_exact_time` (two `int64_t`); layout identity with `fuse::ExactTimeRecord` is `static_assert`ed on both sides; provider `advance` window echo compared numerator/denominator; `AbiParticipant.StepBoundsAreTheSchedulesRationals` pins 1/3 exactly.
- **THE ONE RULE + versioning machinery.** Every entry has the `f(ctx, const IN*, OUT*)` shape; `struct_size` first member everywhere; append-only order enforced three ways (golden header check `gen-abi.py --check`, `struct_sizes.golden` + `AbiGolden.StructSizesMatchTheTable` + the Fortran `C_SIZEOF` mirror, compile-time member-count cross-checks); trailing-padding rule enforced for every struct.
- **Write-side guards.** `declared_out_size` captured before the unconditional `out->struct_size` overwrite in `begin_step`/`end_step`/`is_coupling_ongoing`/`view_field`; every appended member written only under `struct_size_covers`; read-side mirror for `my_component`; heap-exact old-caller tests for `fuse_setup_options`, `fuse_step_report`, `fuse_ongoing`.
- **Handle/lifetime safety.** Handle table is placement-new static storage, never destroyed, mutex-guarded; no pointer dereferenced before liveness check; double `destroy` = `FUSE_ERR_INVALID`; `ConnectedWorld` taken out of the context before `delete` and disconnected after; Kokkos init/finalize via `std::atexit` LIFO matches closed D22 exactly.
- **Registry/dynamic loading.** `RTLD_NOW|RTLD_LOCAL`, `dlerror()` cleared before and consulted after both `dlopen` and `dlsym`, handle closed on every failure path, bootstrap NULL → `E-ABI-VERSION`, `mount_table` validates the table's own `struct_size`/`abi_version` before any member is trusted; `dlclose` ordering vs `ProviderAdapter` destruction correct and *documented with the incident that proved it* (`context.hpp:140-156`, D15). Every refusal path has a real-dlopen negative test.
- **Table version handshake.** v1-caller/v2-table and v2-caller/v1-table both tested, fault-injection via table copy tested. (The library-side `fuse_coupler_abi(v≠1)==NULL` refusal itself is untested — see AB-9.)
- **Fortran bindings.** `bind(C)` interfaces match C signatures; `struct_size` set by the module from `C_SIZEOF`; default initialization = documented defaults; string overloads NUL-terminate into call-lifetime automatic buffers; communicators as Fortran handles with `MPI_Comm_f2c`; provider direction's generated table layout pinned by `sizes_test.f90`; bootstrap returns `c_null_ptr` for wrong version.
- **Docs honesty vs KNOWN_ISSUES (verified item by item).** D15's three "not covered" items match `providers.md` "Open questions" verbatim in substance; D18 matches the `E-CONNECT-SPEC` row in `multiple-executables.md:112`; D17 open and no doc claims window-driver Aitken works; D19/D21/D24/D25/D22 closed entries match code state; D23 open with accept rows documented unrun; the mpmd.3/5 host-run claims are D25's own measured record. No untested capability is claimed as tested anywhere checked.

## 4. Test-coverage assessment

**Participant direction: strong where it counts, thin on negative paths.** The load-bearing behaviors —
exact time (1/3 bounds), suspension timing, subcycled mean, implicit-coupling bit-parity vs in-process,
window-member parity, step-order refusal + non-consumption, run's hosting rule (both directions),
rollover/matched/mismatched, `delivery_pending`/`delivery_field` on every report path, old-caller OUT-struct
sizes, exception containment, error truncation — are all pinned by named tests with in-process oracles.
The gaps are (a) the ~20 unfired refusal codes (AB-9), (b) `view_field` having no test inside `test/abi/`
(its correctness rests on the verification harnesses), (c) `fuse_coupler_abi`'s own version refusal, and
(d) the old-caller **IN**-struct case for `fuse_step_request` (AB-2), which is precisely the one the suite's
own symmetry implies was intended.

**Provider direction: matches its documented, honestly-scoped state.** All four kinds (native/C plugin/
Fortran plugin/participant) run the same fixtures against the native oracle; version/describe/advance/
dlopen/duplicate refusals all fire through *real* dlopen'd misbehaving plugins — the strongest form of
these tests. D15's named absences are real and consistently documented in both `providers.md` and
`KNOWN_ISSUES.md`.

**Fortran: layout- and export-pinned, value-pinned only via the C sibling.** What is *not* tested from
Fortran directly: a value-level comparison against the C consumer (the two print formats are irreconcilable
as written — `consumer.f90:24-31` honestly records this), and the `fuse_last_error_message` truncated path
(AB-5's bug lives exactly there).

**Structural verdict:** the generation/golden discipline (one `.def` → C header, Fortran module, table
initializers, size goldens, symbol lists, member-count static asserts) is the layer's outstanding strength
— drift between the C and Fortran views of the ABI is mechanically impossible, and it held up under this
review. The findings are concentrated where the machinery is hand-written instead of generated: the
`fuse_error` contract (AB-1), the two first-frozen-layout omissions (AB-2/AB-3), and the negative-test sweep
the project's own I4 rule demands (AB-9).
