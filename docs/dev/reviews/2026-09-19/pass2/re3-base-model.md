### N-base-model-3 — MINOR — `error.hpp`'s new Kokkos include is far heavier than what `FUSE_DEBUG_ASSERT` uses

`include/fuse/base/error.hpp:6`, added by commit `4631a8c` ("Make
FUSE_DEBUG_ASSERT callable from device code") — a change made to satisfy a
**backend**-layer finding (R-14/the residual noted in `re-backend.md`: the
native mesh's `measure()`/`centroid()`/`normal()` are `KOKKOS_INLINE_FUNCTION`
but the `FUSE_DEBUG_ASSERT` they called was host-only), not one of this
layer's own findings — but it landed in an owned file, so it is in scope here.

```cpp
// include/fuse/base/error.hpp:6
#include <Kokkos_Core.hpp>  // KOKKOS_IF_ON_HOST/DEVICE and Kokkos::abort for FUSE_DEBUG_ASSERT
```

The comment on the same line names exactly what the file uses —
`KOKKOS_IF_ON_HOST`/`KOKKOS_IF_ON_DEVICE` (used at `error.hpp:222,224`) and
`Kokkos::abort` (used at `:224`) — and grepping the whole file confirms no
other Kokkos symbol is referenced. Both are declared in headers far lighter
than `Kokkos_Core.hpp`: `KOKKOS_IF_ON_HOST`/`_DEVICE` are `#define`d in
`Kokkos_Macros.hpp`, and `Kokkos::abort` is fully defined in
`Kokkos_Abort.hpp`, whose own include list is just `Kokkos_Macros.hpp` and
`Kokkos_Printf.hpp`. `Kokkos_Core.hpp` pulls in the full execution-space,
view, and parallel-dispatch machinery neither macro nor function needs.

**Measured, not asserted.** Preprocessing a one-line translation unit against
each header set with this machine's Kokkos 5.1.0 install
(`c++ -std=c++20 -fopenmp -I /opt/kokkos/include ...`):

| Include | Preprocessed lines | Compile wall time (1 run) |
|---|---|---|
| `<Kokkos_Core.hpp>` alone | 137,342 | 0.87 s |
| `<Kokkos_Macros.hpp>` + `<Kokkos_Abort.hpp>` | 789 | 0.05 s |

And compiling `error.hpp` itself (which also pulls `fmt/format.h` and the
project's generated `config.hpp`, so the baseline is higher) both ways:

| `error.hpp` variant | Preprocessed lines | Compile wall time (1 run) |
|---|---|---|
| As shipped (`Kokkos_Core.hpp`) | 144,023 | 1.14 s |
| Patched to `Kokkos_Macros.hpp`+`Kokkos_Abort.hpp` (compiled in a scratch copy outside the repo, not committed) | 59,802 | 0.49 s |

`error.hpp` is not a peripheral header: it is included, directly or
transitively (every consumer of `Rational`, `Result`, or any `FUSE_ASSERT`/
`FUSE_THROW`/`FUSE_REFUSE` call pulls it in), by effectively every
translation unit in the project — 24 direct includes of
`"fuse/base/error.hpp"` under `include/`, `src/`, `test/` alone, before
counting transitive pulls through `rational.hpp` and friends. This is exactly
the case `docs/dev/layering.md` calls out by name: "`base` through `num` need
only a C++20 compiler, Kokkos and a linear-algebra backend. That is not
minimalism for its own sake: it is what makes the fast CI leg fast." Kokkos
itself was already a mandatory dependency at this layer before this change
(so this is not a new *dependency*, and `tools/check-layering.py`'s
`ALLOWED_PUBLIC_THIRD_PARTY["base"] = {"Kokkos_Core.hpp"}` explicitly permits
this exact header, so the layering gate does not and should not flag it) —
the regression is in *how much* of Kokkos the lowest, most-included header in
the project now pulls in for two symbols, working against the layering
doc's own stated rationale for keeping this layer light.

**Confirmed reachable/real**, not merely a style preference: I compiled a
scratch copy of `error.hpp` with the include swapped to
`<Kokkos_Macros.hpp>`+`<Kokkos_Abort.hpp>` (kept outside the repo tree, not
committed, consistent with this task's read-only constraint) and it compiles
`FUSE_DEBUG_ASSERT(1 == 1)` cleanly with the same toolchain — the swap is a
drop-in replacement, not a design tradeoff that needs anything else from
`Kokkos_Core.hpp`.

**Fix.** Replace `include/fuse/base/error.hpp:6`'s
`#include <Kokkos_Core.hpp>` with `#include <Kokkos_Macros.hpp>` and
`#include <Kokkos_Abort.hpp>`.

**Test to add.** None needed for correctness — this is a compile-cost
regression, not a behavioral one, and the existing `base.error` suite
(unchanged, still 3/3 relevant cases green) already covers
`FUSE_DEBUG_ASSERT`'s host-side behavior. If the project wants a standing
guard against this class of regression, a `tools/check-invariants.py` rule
forbidding `Kokkos_Core.hpp` in `include/fuse/base/*.hpp` (steering base-layer
headers toward the narrower Kokkos headers, mirroring the existing
third-party-header allowlist mechanism) would catch a future reintroduction,
but that is a suggestion, not a requirement of this finding.
